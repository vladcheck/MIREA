# 0004: Аутентификация — Keycloak SSO с email-OTP (двухшаговый инструмент), refresh-токены в state-файле

Пульс авторизуется через единый SSO вуза (Keycloak, `sso.mirea.ru/realms/mirea`, клиент `attendance-app`, PKCE). При входе МИРЭА может потребовать OTP — код приходит на корпоративную почту @edu.mirea.ru. Автоматизированное чтение почты в v1 не делаем: MCP-сервер реализует двухшаговый вход инструментами (`mirea_auth_start` → пользователь читает код на почте → `mirea_auth_otp`), после которого access/refresh-токены сохраняются в gitignored state-файле; сервер проактивно рефрешит сессию, а при умершем refresh-токене инструменты возвращают ошибку «требуется повторный вход». СДО: ~~использует ту же пару логин/пароль через `login/token.php`~~ — парольные пути удалены (ADR-0005); рабочий вход — OIDC-заезд на SSO-сессии Пульса.

**Status**: proposed (поток входа подтверждён смоук-тестом с реальными учётными данными; парольная часть СДО устарела — удалена в ADR-0005: MCP не отправляет пароль в Moodle ни в одном режиме, REST доступен только через MIREA_SDO_TOKEN)

**Considered Options**: автоматическое чтение OTP из почты через IMAP/API (отвергнуто для v1: лишний доступ к почте; возможно позже); разовый CLI-helpers вместо MCP-инструментов (отвергнуто как основной путь: OTP-шаг удобнее проходить в диалоге с агентом; CLI остаётся возможным fallback).

**Consequences**: `pulse.mirea.ru` блокирует IP датацентров — MCP должен работать с машины пользователя, не с сервера; state-файл с токенами — только локально, права 0600, каталог в `.gitignore`.
