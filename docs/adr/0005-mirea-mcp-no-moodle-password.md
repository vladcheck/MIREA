# 0005: MCP никогда не отправляет пароль в Moodle — вход в СДО только через OIDC-заезд на SSO-сессии Пульса

**Status**: accepted

## Контекст

В день запуска (2026-11-22) учётная запись СДО была автоматически заблокирована **четыре раза** (10:09, 10:20, 10:23, 10:43). Причина: каждый вызов инструмента, обращающегося к СДО, — это новый процесс MCP-сервера, а цепочка авторизации начиналась с REST-режима: `login/token.php` получал **верный** SSO-пароль и отвечал `invalidlogin` — Moodle считает каждый такой ответ неудачной попыткой входа, и после ~4 попыток аккаунт блокируется (письмо со ссылкой-разблокировкой приходит на почту). Эмпирически установлено:

- Верный пароль Keycloak (sso.mirea.ru) **не принимается** Moodle ни в token.php, ни в локальной форме `/login/index.php` — локальная auth СДО отключена/разорвана с SSO.
- Разблокировка — только по одноразовой signed-ссылке из письма; повторные блокировки наступают быстро при любом продолжающемся пробнике.
- Здоровый вход в СДО: OIDC (`/auth/oidc/`, client_id `moodle`) заезжает на Keycloak SSO-сессию, которую выдаёт вход в Пульс (`client_id attendance-app`). Keycloak отвечает `response_mode=form_post` — авто-сабмит HTML-формы code/state обязателен вручную.
- OTP от Keycloak уходит на @edu.mirea.ru и **редиректится на yandex-почту** пользователя.

## Решение

MCP **не отправляет пароль в Moodle ни в одном режиме**. Парольные пути (`token.php`-обмен, локальная форма входа) удалены из кода. Цепочка авторизации СДО: восстановление сохранённой сессии → OIDC-заезд на SSO-куках Пульса → `SdoAuthError` с подсказкой «выполните вход в Пульс». REST-режим существует исключительно при ручной установке `MIREA_SDO_TOKEN` (dormant escape-hatch: REST на online-edu отключён на уровне функций, но вуз может включить). Единственный интерактивный вход — Пульс (Keycloak, email-OTP, refresh-токены в `.state/`).

## Considered Options

- Оставить пробник token.php с бэкоффом/лимитом — отвергнуто: любая отправка верного пароля, который Moodle не примет, рискует блокировкой; надёжного сигнала «пароль примут» нет.
- Пробовать пароль только по явному флагу — отвергнуто: тот же класс риска, плюс конфигурационная сложность и соблазн включить.
- Локальная форма как fallback при смерти SSO-сессии — отвергнуто: форма шлёт пароль туда же, где он гарантированно отклоняется.
- Авточтение OTP из почты — по-прежнему отложено (не потребовалось: двухшаговый MCP-вход удобен).

## Consequences

- Новый режим отказа: сессия Пульса мертва → инструменты СДО возвращают ошибку с подсказкой вместо «самолечения» паролем. Это осознанный trade-off: блокировка аккаунта хуже, чем один лишний вызов `mirea_auth_start`.
- Семантика `MIREA_SDO_TOKEN` изменена (см. ADR-0002/0004): теперь это единственный путь в REST, а не override к авто-обмену.
- Проверено: grep не находит отправки пароля в Moodle; live-верификация проходит без единого парольного запроса.
- Подробная эксплуатационная память (дрейф protobuf Пульса, form_post, доменные куки, пре-маркированные future-absent, long-lived процесс сервера) — в managed skill `mirea-mcp-runbook` и README пакета.
