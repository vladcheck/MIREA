# ПлатформIO-проекты для стенда DIS_F407VG (STM32F407VGT6)

Дисциплина «Программирование электронных приборов и систем».
Каждая лабораторная — отдельный проект в своей папке, код на регистрах CMSIS,
framework — STM32Cube (`stm32f4xx.h`), плата — `genericSTM32F407VGT6`.

| Папка              | Лабораторная                        | Что делает                                       |
| ------------------ | ----------------------------------- | ------------------------------------------------ |
| `LR1_GPIO_LED`     | ЛР №1. GPIO                         | Мигание и «бегущий огонь» на светодиодах PA0–PA7 |
| `LR2_SevenSegment` | ЛР №2. Семисегментный индикатор     | Статическая/динамическая индикация, 4 разряда    | *(скрыт из меню)* |
| `LR3_LogicGen`     | ЛР №3. Генератор логических уровней | Опрос свитчей, антидребезг, вывод кода 0–15      | *(скрыт из меню)* |

Проекты LR2/LR3 скрыты из меню Lab Runner маркером `.labrunner-hide` (сами проекты на диске остаются и собираются). Чтобы вернуть проект в меню — удалите этот файл из его папки.

## Требования

- Установлены: `platformio` (brew), `stlink` (brew), расширение PlatformIO IDE в VS Code.
- Стенд подключён к Mac по USB, питание — от USB-шины.

Проверка соединения со стендом:

```bash
st-info --probe
# Должно показать: version V2J..., chipid 0x413, dev-type STM32F4x5_F4x7
```

## Сборка и прошивка из терминала (CLI)

Все команды выполняются **из папки проекта** (`platform_io_projects/LR1_GPIO_LED` и т.д.):

```bash
cd platform_io_projects/LR1_GPIO_LED

pio run                    # только собрать (результат: .pio/build/dis_f407vg/firmware.bin)
pio run --target upload    # собрать и прошить через ST-LINK
pio run -t clean           # очистить сборку
```

## Сборка и прошивка из VS Code

1. `File → Open Folder…` → выбрать папку проекта (например, `LR1_GPIO_LED`).
2. На панели PlatformIO (иконка «алien» слева) раздел **Project Tasks → dis_f407vg**:
   - **Build** — сборка;
   - **Upload** — прошивка стенда (при прошивке мигает индикатор АКТ);
   - **Monitor** — терминал (в этих ЛР не используется).
3. Либо кнопки в статус-баре внизу: ✓ (Build) и → (Upload).

## Выбор задачи/режима внутри проекта

Режим задаётся макросом в начале `src/main.c` (можно менять в коде или собрать флагом, не редактируя файл):

```bash
# LR1: MODE 1 - мигание PA0; 2 - огонь вперёд; 3 - огонь назад; 4 - двухсторонний; 5 - скорость
PLATFORMIO_BUILD_FLAGS="-DMODE=3" pio run --target upload

# LR3: TASK 0 - основная программа; 1 - инвертор; 2 - режимы LED; 3 - счётчик 0-9; 4 - двоичный вывод
PLATFORMIO_BUILD_FLAGS="-DTASK=2" pio run --target upload
```

В VS Code флаг можно прописать временно в `platformio.ini`:
```ini
build_flags = -DMODE=3
```

## Пин-маппинг стенда (общий для всех ЛР)

| Сигнал          | Выводы  | Примечание                                             |
| --------------- | ------- | ------------------------------------------------------ |
| Светодиоды      | PA0–PA7 | Активный высокий уровень (в ЛР1); в ЛР3 LED на **PA7** |
| Сегменты a–g    | PA0–PA6 | Бит0=a … бит6=g, таблица `SEG_CODE`                    |
| Катоды разрядов | PC0–PC3 | Активный низкий: 1 = разряд погашен, 0 = включён       |
| Свитчи SW1–SW4  | PB0–PB3 | Входы с подтяжкой вверх, замыкание на GND = «1» в коде |

## Интерактивное меню (Lab Runner)

В папке `menu/` — утилита с градиентным TUI-меню (`@clack/prompts`): выбор проекта → выбор MODE/TASK → сборка/прошивка одним кликом.

```bash
cd menu
npm install     # один раз
npm start       # интерактивное меню
```

Без меню (для скриптов): `node cli.mjs <проект> <upload|build|clean|code> [--mode N|--task N]`,
например `node cli.mjs LR1_GPIO_LED upload --mode 3`.

## Если прошивка не идёт

1. `st-info --probe` видит стенд? Если нет — проверьте кабель и USB.
2. OpenOCD (протокол `stlink`) не поддерживает старые ST-LINK/V1 — тогда в `platformio.ini` раскомментируйте fallback и прошивайте через `st-flash`:

```ini
upload_protocol = custom
upload_command = st-flash write $SOURCE 0x8000000
```

3. Порт занят другим процессом (монитор/отладчик) — закройте его.
