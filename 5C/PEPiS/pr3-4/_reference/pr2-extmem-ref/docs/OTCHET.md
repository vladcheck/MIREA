## 1. Наименование и цель работы (п. 2.2.4-1)

Наименование: «Подключение внешней памяти и её тестирование».
Цель: разработать схему подключения микроконтроллера МК-51 (8051) с внешней
памятью (ОЗУ + ПЗУ) через регистр-защелку и протестировать память:
- Задание 1 — внешнее ОЗУ N Кбайт, тест 1 Кбайт с адреса ZZZ паттерном XX,
  LED при несовпадении записанного/считанного; осциллограмма ALE;
- Задание 2 — внешнее ПЗУ N Кбайт, контрольная сумма K байт с адреса ZZZ,
  сравнение с эталоном резидентного ПЗУ, LED при несовпадении; осциллограмма ALE.

Варианты — `variants.json` (табл. 8: Вар.1–6; табл. 9: Вар.7–12).
В ТЗ правило выбора варианта не указано, поэтому решение параметрическое,
демо: **Вар.1 (ОЗУ 8К, XX=0AAh, ZZZ=0800h) + Вар.7 (ПЗУ 8К, K=100, ZZZ=0800h)**.
Любой другой вариант включается заменой 2–3 строк `EQU`/`define` (таблица в шапке
каждого файла `prog/`) и прогоняется тем же симулятором.

## 2. Микросхемы памяти и осциллограф (п. 2.2.4-2)

### 2.1. ОЗУ: HM6116A120 (2К×8, Вар.2/6) / HM1-65642-883 (8К×8, Вар.1/3/4/5)
В KiCad-схеме — `U2 HY6264AxP` (8К×8 SRAM, DIP-28), функциональный аналог:
для 2К-вариантов используются только A0–A10, старшие адреса притянуты к GND
(см. текст на схеме). Выводы (одинаковы у 6116/6264/65642, отличается число A):
- `A0–A12` (11/13 входов: 2К — A0–A10, 8К — A0–A12) — адрес;
- `I/O0–I/O7` (D0–D7) — двунаправленная шина данных (к P0 напрямую);
- `~CS1/CS2` (`CS`, `E1/E2`) — выбор кристалла: `CS=1` — отключена, `CS=0` — обращение разрешено;
- `~WE` (`W`) — направление: `1` — чтение, `0` — запись;
- `~OE` (`G`) — `0` разрешает выходную шину данных;
- `VCC` (+5В), `GND`.
В схеме: `~CS1←RAM_CS` (дешифратор), `CS2←+5В`, `~WE←/WR (P3.6)`, `~OE←/RD (P3.7)`.

### 2.2. ПЗУ: 27C64 (8К×8, Вар.7/10) / 27C128 (16К×8, Вар.8/11) / 27C256 (32К×8, Вар.9/12)
В схеме — `U4 27C64` (DIP-28), для 16К/32К — тот же корпус, добавляются A13/A14
(см. текст на схеме). Только чтение в рабочем режиме. Выводы как у ОЗУ, плюс:
- `~CE` — выбор кристалла (`←ROM_CS` от дешифратора);
- `~OE` — разрешение выхода (`←/PSEN` — выборка программы, см. п. ответов 3);
- `~PGM`, `VPP` — только для программирования (в рабочем режиме `VPP←+5В`, `~PGM←+5В`);
- `A0–A14` (8К — A0–A12, 16К — +A13, 32К — +A13–A14), `D0–D7`, `VCC`, `GND`, `NC`.

### 2.3. Регистр-защелка U3 74LS373 (аналог 74LS373N / 4037BP из методички)
Фиксирует младший байт адреса A0–A7 с мультиплексированной шины P0 (AD0–AD7)
по **спаду ALE** и держит его весь машинный цикл. `D0–D7←AD0–AD7`, `O0–O7→A0–A7`,
`LE←ALE`, `OE←GND` (всегда разрешён). Без неё адрес бы пропал, когда P0
переключится с адреса на данные.

### 2.4. Виртуальный осциллограф XSC1 (рис.28)
Два канала: `Ch.A «+» → ALE/PROG МК`, `Ch.B «–» → GND`.
Настройки: развёртка **1 мкс/дел = 1 машинный цикл** (12 МГц: 12 периодов = 1 мкс),
усиление **5 В/дел** по Y. Наблюдается генерация ALE — **два импульса за машинный
цикл** (стробы фиксации адреса для двух обращений к памяти за цикл).
В KiCad-схеме прибор — корпус `XSC1 Conn_01x02` (1-Ch.A→`ALE`, 2-Ch.B→`GND`)
плюс текстовая метка `XSC1-ALE-PROBE` на цепи `ALE`;
сама осциллограмма синтезирована в `sim/test_ale.py` → `out/ale_oscillogram.png`,
`out/ale_waveform.csv` (уровни 0/5В, 4 цикла = 4 мкс, 8 фронтов).

## 3. Схема (п. 2.2.4-3)

Файл: `PR2_extmem.kicad_sch` (генератор `generate_schematic.py`, KiCad 10, лист A3).
Открыть: `kicad PR2_extmem.kicad_sch` или через `PR2_extmem.kicad_pro`.

Состав (позиционные обозначения):
- `U1 P8051AH` (DIP-40) — МК-51; `EA←+5В`, `RST` — R2 10к/C3 10мкФ, `XTAL1/2` — `Y1 12МГц + C1/C2 33пФ`;
- `U3 74LS373` — защелка; `LE←ALE`, `D←AD`, `Q→A`, `OE←GND`;
- `U2 HY6264` — ОЗУ (подпись содержит N и вариант);
- `U4 27C64` — ПЗУ (подпись содержит N и вариант);
- `U5 74LS138` — дешифратор CS (`A13→A0, A14→A1, A15→A2, E1/E2→GND, E3→+5В, O0→RAM_CS, O4→ROM_CS`);
- `XSC1 Conn_01x02` — осциллограф (`1→ALE`, `2→GND`);
- `R1 330 + D1 LED-RED:ERROR` — индикатор ошибки на `P1.0` (`P1.0→R1→D1→GND`);
- `R2/C3` — сброс, `Y1/C1/C2` — тактирование, `+5V/GND/PWR_FLAG` — питание (цепи `+5V`/`GND`).
- Выводы `NC` у U2/U4 (тип no-connect внутри корпуса) оставлены свободными.
- `C1/C2/C3` — footprint `C_Disc_D4.3mm_W1.9mm_P5.00mm`.

Шины (эквивалент Multisim Bus1/Bus2 + Merge):
- `AD0–AD7`: `U1 P0.0/AD0…P0.7/AD7 ↔ U3 D0–D7 ↔ U2 I/O0–I/O7 ↔ U4 D0–D7`;
- `A0–A7`: `U3 O0–O7 ↔ U2 A0–A7 ↔ U4 A0–A7`;
- `A8–A15`: `U1 P2.0/A8…P2.7/A15 ↔ U2/U4 A8–A12 ↔ U5 A0–A2 (A13–A15)`;
- управление: `ALE` (U1→U3 + XSC1.1), `/WR (P3.6)→U2 ~WE`, `/RD (P3.7)→U2 ~OE`, `/PSEN→U4 ~OE`, `RAM_CS (U5.O0→U2 ~CS1)`, `ROM_CS (U5.O4→U4 ~CE)`, `LED_ERR`, `RST`, `XTAL1/2`.
Карта памяти (текст на схеме): `RAM_CS=O0` (ОЗУ `0000h–1FFFh = !A15&!A14&!A13`),
`ROM_CS=O4` (окно ПЗУ `8000h–9FFFh`, полное ПЗУ `8000h+` — ИЛИ O4–O7); для 2К-вариантов A11–A12 → GND.
Неиспользованные `P1.1–P1.7`, `P3.0–P3.5` и `U5.O1–O3,O5–O7` — `no-connect`; питание `+5V`/`GND`.
ERC: 0 нарушений (`kicad-cli sch erc`).

Соответствие рис.25: мультиплекс P0, фиксация по спаду ALE, старший адрес с P2,
стробы `/RD//WR` с P3.7/P3.6, `Built-in External RAM = N Кбайт` — в подписи `U2`
и в `variants.json`. Скриншот схемы прикладывается из KiCad (лист A3 целиком).

## 4. Программы (п. 2.2.4-4, с подробными комментариями — см. файлы `prog/`)

### 4.1. `prog/prog2_ram_test.asm` — Задание 1, ассемблер (демо Вар.1)
Идея методички (255 байт с `00h`, паттерн `055h`), расширенная до **1 Кбайт =
4×256 двойным циклом** (`R2` внешний, `R3` внутренний — иначе счётчик не влезает,
см. методичку: «>255 байт — двойные циклы»). Алгоритм на ячейку:
`MOV A,R1 → MOVX @DPTR,A (/WR) → MOVX A,@DPTR (/RD) → XRL A,#XX → JNZ ERROR →
INC DPTR → DJNZ`. Ошибка: `SETB P1.0` + вечный цикл (LED горит, точка останова).
Успех: `P1.0=0`, `DPTR=ZZZ+1024`. Полный текст с шапкой замен для Вар.2–6 — в файле.

### 4.2. `prog/prog2_ram_test.c` — Задание 1, Си (демо Вар.1)
То же через `__xdata`-указатель с `0x0800`, цикл `for (i=0;i<1024;i++)`:
`*ptr=nabor; test=*ptr; if(test!=nabor){P1_0=1;break;} ptr++;`.
16-битный `int i` снимает проблему двойного цикла — иллюстрация тезиса методички
«большие массивы легче на Си». Компиляция: SDCC/Keil C51, модель SMALL.

### 4.3. `prog/prog2_rom_checksum.c` / `.asm` — Задание 2 (демо Вар.7)
`K=100` байт с `0x0800`, сумма `mod 256`, сравнение с `ROM_REF=0x56` из
«резидентного ПЗУ». Си: `sum+=*ptr`. Асм: `MOVC A,@A+DPTR` (строб `/PSEN`),
16-битный счётчик `R2:R3`, сумма в `R4`, `XRL A,#ROM_REF → JZ OK / SETB P1.0`.
Эталоны всех вариантов (стенд: содержимое = младший байт адреса):
Вар.7 `56h`, Вар.8 `32h`, Вар.9 `4Eh`, Вар.10 `0A7h`, Вар.11 `93h`, Вар.12 `0EDh`
(посчитаны скриптом, проверены симулятором). Совпало → тест пройден (`P1.0=0`),
иначе → LED (`P1.0=1`).

Сборка по Multisim: `MCU → MCU 8051 U1 → Build`, `Show lines numbers` для номеров
строк ошибок; отладка: `Simulate → Run (F5)`, `Step into (F11)`, `Pause (F6)`,
`Stop`, `Memory view / MCU Windows`, `Toggle breakpoint`.
Здесь эквивалент: `bash run.sh` (сборка = генерация схемы, отладка = тесты + JSON).

## 5. Результаты и выводы (п. 2.2.4-5)

Прогон: `bash run.sh` → `python3 sim/run_all.py` (эмулятор шины `sim/mcu8051_bus.py`
повторяет физику схемы: спад ALE→фиксация 373, P2→A8–A15, `/WR//RD`→XRAM,
`/PSEN`→ПЗУ, `P1.0`→LED).

- **ОЗУ (все 6 вариантов, по 1024 ячейки + негативный тест с порчей):**
  `out/ram_results.json` — `write_read_ok=true`, `led_on_fault=true` во всех
  вариантах (Вар.1 `0AA/0800`, Вар.2 `55/0100`, Вар.3 `00/0C00`, Вар.4 `FF/1000`,
  Вар.5 `55/1400`, Вар.6 `0AA/0400`). Первая ячейка после `DJNZ` содержит XX
  (как рис.27: `R1=XX`, `ACC=0` после `XRL`, счётчик уменьшился на 1).
  После полного прогона вся область `ZZZ…ZZZ+1023` = XX, `P1.0=0`; при инъекции
  ошибки `P1.0=1` — LED отрабатывает.
- **ПЗУ (все 6 вариантов + негативный тест):**
  `out/rom_results.json` — суммы совпали с эталонами
  (`56h/32h/4Eh/0A7h/93h/0EDh`), при порче байта суммы расходятся и LED=ON.
- **ALE:** `out/ale_waveform.csv` + `out/ale_oscillogram.png` — 4 машинных цикла
  = 4.0 мкс, 8 нарастающих фронтов (2/цикл), уровни 0/5В — как рис.28
  (1 мкс/дел, 5 В/дел).

Выводы:
1. Защелка обязательна: без фиксации по спаду ALE младший адрес теряется при
   переходе P0 с адреса на данные.
2. Тест ОЗУ — только записью+чтением (память меняется), тест ПЗУ — только
   контрольной суммой (запись невозможна) — см. ответы 10, 7.
3. Си удобнее asm при областях >255 байт (16-битный счётчик против двойного цикла).
4. LED на `P1.0` корректно различает норму/брак в обе стороны (позитивные и
   негативные тесты PASS).
5. ALE стабилен: 2 импульса/цикл, что подтверждает правильность тактирования
   защелки и стробов `/RD//WR//PSEN`.

## Ответы на вопросы для самоконтроля (п. 2.2.5)

1. **Функции регистра-защелки (373):** фиксация младшего байта адреса A0–A7 с
   мультиплексированной шины P0 (AD0–AD7) по спаду ALE и удержание его весь
   машинный цикл, пока P0 несёт данные. Иначе адрес пропадёт.
2. **Альтернативная функция P2:** старший байт адреса A8–A15 внешней памяти
   программ/данных (включается записью `1` в биты-защелки порта).
3. **PSEN (выв. 29, в тексте — 37 по другому корпусу):** строб чтения внешней
   памяти программ (`0` — выборка кода из ПЗУ); для XRAM-данных используется
   `/RD`, для записи — `/WR`.
4. **Внешняя vs резидентная память данных:** резидентная — однотактные `MOV`
   во внутреннее ОЗУ/регистры; внешняя — через `MOVX @DPTR` с машинными циклами
   шины: ALE + фиксация 373 + P2 + строб `/RD//WR` (медленнее, нужны внешние
   кристаллы и защелка).
5. **EA/Vpp:** `EA=1` — старт из внутреннего ПЗУ (внешнее — только по адресам выше
   внутреннего), `EA=0` — вся программа из внешнего ПЗУ; при программировании —
   `Vpp` (+12/21В). В схеме `EA←+5В`.
6. **Одно ОЗУ и для данных, и для программы (фон-Нейман):** соединить `/RD` и
   `/PSEN` через И (или посадить ОЗУ на оба строба через дешифратор) + `EA=0`
   для адресов программы; тогда код выбирается и `MOVC//PSEN`, и `MOVX//RD`.
   Классика 8051 — Гарвард (`/PSEN`↔ПЗУ, `/RD//WR`↔ОЗУ), объединение — через
   внешнюю логику.
7. **Контрольная сумма:** `SUM = (Σ ROM[i]) mod 256` (или mod 65536 / CRC) по
   области `ZZZ…ZZZ+K-1`, затем сравнение с эталоном из резидентного ПЗУ;
   равенство = ПЗУ цело, иначе — LED. Здесь 8-битная сумма (см. эталоны п.4.3).
8. **CE(CS)/OE:** `CE/CS=0` — кристалл выбран (иначе выходы в Z и ток покоя),
   `OE=0` — выход данных разрешён (иначе Z даже при выбранном кристалле);
   комбинация `CE=0&OE=0&WE=1` — чтение, `CE=0&WE=0` — запись (ОЗУ).
9. **PROM vs EPROM:** PROM — однократно программируемая (пережигаемые перемычки/
   floating-gate без окна, дешевле, не стирается); EPROM (27Cxxx) — с УФ-окном,
   стирается УФ (~15–20 мин) и перепрограммируется в программаторе (`VPP/~PGM`);
   конструктивно — окно + floating-gate с туннелированием, технологически дороже.
10. **Тестирование ОЗУ vs ПЗУ:** ОЗУ — деструктивный тест запись→чтение→сравнение
    (паттерны `AAh/55h/00h/FFh`, «бегущий», адресный; область можно затирать);
    ПЗУ — неразрушающий: только чтение + CRC/сравнение с эталоном (запись в
    рабочем режиме невозможна; шьётся отдельно, проверяется сохранность).
