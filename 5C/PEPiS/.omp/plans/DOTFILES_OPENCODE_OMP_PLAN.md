# Plan: dotfiles `.config/opencode/` → `.omp/` user-config migration

## Context

User dotfiles hold live OpenCode user config at `~/dotfiles/.config/opencode/` (`opencode.json`, `AGENTS.md`, 4 `commands/`, 2 `agents/`, `_plugins/` TS hook, `dcp.jsonc`, plugin build files). OMP already imports OpenCode user config through its `opencode` discovery provider, but the ask is an explicit native copy under `~/dotfiles/.omp/` (the repo already tracks a `.omp/` tree: `agent/`, `cache/`, `logs/`, `run/`, `install-id`, `natives/`). User chose: keep both configs after migration (opencode stays as fallback), and carry the three disabled MCP servers as `disabledServers`. End state: native `~/.omp/agent/` equivalents for MCP, context, commands, agents, permissions, and the git-commit format hook, verified via `/mcp list`, command/skill resolution, and a clean startup with no discovery warnings.

## Approach


0. **Confirm the stow mapping before writing anything (user uses stow).** `~/dotfiles/.omp/` is a stow package that should deploy to `~/.omp`. Implementer MUST check live links first: `ls -la ~ | grep -E '^\S+ +[^ ]+ \.omp|\.config'`, `readlink ~/.omp ~/.config/opencode`, and `stow -nvs -d ~/dotfiles -t ~ .omp 2>&1 | head`. If `~/.omp` is a real directory instead of a stow symlink tree, determine whether `.omp` was ever stowed (`stow -nvs` preview) vs manually copied; deploy new files into `~/dotfiles/.omp/...` then `stow -R -d ~/dotfiles -t ~ .omp` (or the repo's documented stow invocation) so dotfiles stays the source of truth. All edits below go to the dotfiles side; re-stow, do not hand-copy into `~`. Runtime state (`cache/`, `logs/`, `run/`, `*.db*`, `install-id`, `natives/`) MUST NOT be committed if not already tracked — check `git -C ~/dotfiles status --short` first and leave untracked runtime files alone.
1. **Copy `AGENTS.md` to the native user slot verbatim.** New file `<dotfiles-.omp>/agent/AGENTS.md`, byte-for-byte from `~/.config/opencode/AGENTS.md` (4 bullets: nx/stdout, subagent timestamps, rg-over-grep, worktree absolute paths). Rationale: native `~/.omp/agent/AGENTS.md` has highest user priority and shadows the opencode-provider copy, so behavior is identical with zero edits. (The `rg` bullet is already satisfiable: user config sets `find.enabled: "on"`.)
2. **Migrate the 4 ponytail commands — target dir confirm-first.** OMP equivalent of opencode `commands/*.md` is unverified: implementer MUST resolve it first (`omp config list --json | grep -i command`, plus `omp://` commands docs): expected candidates are `~/.omp/agent/commands/*.md`. Then copy the 4 files (`ponytail.md`, `ponytail-review.md`, `ponytail-debt.md`, `ponytail-audit.md`) verbatim — frontmatter `description` + body. If OMP command arg syntax differs from opencode `{{args}}`, adapt ONLY that token per docs, nothing else. If no user-commands slot exists, fallback (pre-decided): convert each to a skill at `<dotfiles-.omp>/agent/skills/ponytail*/SKILL.md` (add `name:` frontmatter = directory name; `description` already present satisfies `requireDescription:true`) and record the `/skill:ponytail` invocation change.
3. **Migrate the 2 agents — slot confirm-first.** `agents/explorer.md` (strict read-only: `read/glob/grep` only) and `agents/teach.md` (`mode: primary`, `temperature: 0.1`, tool allow/deny map incl. `external_directory: allow`) are opencode-agent schema, not OMP `task` agents. Implementer MUST check the `/agents` hub + `task.*` settings for a user custom-agent slot first. No slot found → fallback (pre-decided): `explorer` becomes a skill (`skills/explorer/SKILL.md`: keep Mission/Hard-restrictions/Output-style body, add `name: explorer`, keep `description` sentence); `teach` becomes `skills/teach/SKILL.md` the same way, DROPPING the opencode tool-permission frontmatter (unenforceable in a skill — note it inline as prose: "decline edits/execution, offer read-only analysis"). Never invent temperature/mode knobs in skill frontmatter (not in the supported set: `name/description/globs/alwaysApply/hide/disableModelInvocation/enabled`).
4. **Port the format-on-precommit hook to an OMP extension; drop `dcp.jsonc`.**
   - New file `<dotfiles-.omp>/agent/extensions/format-on-precommit.ts`: `export default function (pi) { pi.on("tool_call", async (event) => { if (event.toolName !== "bash" || !String(event.input.command ?? "").includes("git commit")) return; ... run `npx nx run x5m-web:format:fix` via `pi.exec`, log via `pi.logger` ... }) }`. Replace `@opencode-ai/plugin` `Client/$/app.log` + `shared/Service.ts` + `shared/types.ts` with the `HookAPI` shape (`pi.exec`, `pi.logger`); do NOT copy the `shared/` dir or `node_modules/pnpm*/tsconfig/package.json` (opencode-plugin build scaffolding, useless to OMP — stays in `.config/opencode/` per keep-both).

## Assumptions & contingencies

- Assumption: dotfiles `.omp/` is the deployed source for `~/.omp` (same mechanism as `.config/opencode`). If step 0 shows it is a stale copy instead: write to live `~/.omp/agent/...` AND mirror into dotfiles per whatever mechanism the repo uses — do not leave the two diverged without a note.
- Assumption: OMP `headers` values expand `${VAR}` like `env` does. If `/mcp test keenable` proves otherwise: use `/mcp auth keenable` and drop the header (step 1 fallback, no new decision).
- Assumption: a user commands slot and a custom-agent slot exist with `*.md` layout analogous to skills. If either is absent/different: skill-conversion fallback (steps 3–4) applies, no new decision needed.
- Scope edge (user-chose keep-both): `.config/opencode/` is never deleted or edited except by explicit later request; identical-body dedup may hide the opencode copy of a same-named skill — that is expected shadowing, not an error.
