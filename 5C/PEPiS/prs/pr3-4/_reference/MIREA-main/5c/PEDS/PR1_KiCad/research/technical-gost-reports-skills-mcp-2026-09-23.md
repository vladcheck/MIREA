## Technology Landscape

### Overview of Approaches

Три уклада сосуществуют в RU-сегменте: LaTeX-классы, нативные Word-шаблоны с макросами и связка Markdown → pandoc → docx с CSL-библиографией, поверх которой в 2025–2026 надстраиваются python-docx-скрипты, AI-скиллы и generic MCP-серверы. Выбор определяется точкой входа: вуз с LaTeX-традицией берёт класс, студент с готовой курсовой — Word-нормализатор, AI-агент — генерацию docx из Markdown.

LaTeX-направление — самое формализованное. Коллекция классов eskdx предназначена для вёрстки по российским стандартам, включая ЕСКД [CTAN — Package eskdx](https://ctan.org/pkg/eskdx?lang=en) (accessed 2026-09-23, confidence: High). Класс `G7-32` с `preamble.inc.tex` и командами `\frontmatter/\mainmatter/\backmatter` реализует структуру отчёта о НИР [Overleaf — Template GOST 7.32-2001](https://ru.overleaf.com/latex/templates/template-gost-7-dot-32-2001/fvmgmhqyvdcx) (accessed 2026-09-23, confidence: High). Более свежая попытка под редакцию 2017 года — documentclass с опциями `12pt/14pt` [GitHub — weterans/gost](https://github.com/weterans/gost) (accessed 2026-09-23, confidence: Medium). Сильная сторона — диссертации и формулы; слабая — требование вуза «сдать именно .docx».

Word-направление — доминирующее по объёму артефактов. Базовые параметры (Times New Roman 14, полуторный интервал, красная строка 1,25 см, поля 30/15–10/20/20 мм) подтверждаются вузовской выпиской и текстом стандарта [СПбГУПТД — выписка из ГОСТ 7.32-2017](http://iskd.sutd.ru/wp-content/uploads/2019/04/%D0%9E%D1%84%D0%BE%D1%80%D0%BC%D0%BB%D0%B5%D0%BD%D0%B8%D0%B5%D0%9E%D1%82%D1%87%D0%B5%D1%82%D0%B0_%D0%9A%D1%80%D0%B0%D1%82%D0%BA%D0%B0%D1%8F-%D0%B2%D1%8B%D0%BF%D0%B8%D1%81%D0%BA%D0%B0-%D0%B8%D0%B7-%D0%93%D0%9E%D0%A1%D0%A2-%D1%81-%D0%9F%D1%80%D0%B8%D0%BC%D0%B5%D1%80%D0%B0%D0%BC%D0%B8-2019.pdf) (accessed 2026-09-23, confidence: High), [ГУАП — ГОСТ Р 2.105-2019](https://guap.ru/standards/db/docs/GOST_R_2.105-2019.pdf) (accessed 2026-09-23, confidence: High). На этом фундаменте: шаблоны `.dotx/.docm` с автонумерацией [GitHub — konstantin-morenko/report-732-2017](https://github.com/konstantin-morenko/report-732-2017) (accessed 2026-09-23, confidence: Medium), пара `gost-reference.docx / gost-reference.dotx` [GitHub — mikeGEINE/pandoc-templates](https://github.com/mikeGEINE/pandoc-templates) (accessed 2026-09-23, confidence: Medium); нормализаторы на python-docx: библиотека `WordBuilder + ElementFactory + IndexManager` со сквозной/поглавной/пристатейной нумерацией [PyPI — gost-docx 0.2.7](https://pypi.org/project/gost-docx/0.2.7/) (accessed 2026-09-23, confidence: High), CLI-нормализатор с флагами `--check --margins --page-number` [GitHub — samikofficial/gostdoc](https://github.com/samikofficial/gostdoc) (accessed 2026-09-23, confidence: Medium), GUI-форматтер на PyQt5 [GitHub — Ivadus/GOST-Wordx](https://github.com/Ivadus/GOST-Wordx) (accessed 2026-09-23, confidence: Low); агентский CLI поверх Word COM только под Windows [GitHub — MaximillianVoss/ai-vkr-gost-kit](https://github.com/MaximillianVoss/ai-vkr-gost-kit/blob/main/README.md) (accessed 2026-09-23, confidence: Medium).

Тракт Markdown → docx через pandoc — de facto стандарт для связки «пишу в Markdown, сдаю в Word». Каноническая команда — `pandoc -i INPUT -o OUT.docx --reference-doc="gost-reference.docx"` плюс `--citeproc` с CSL [GitHub — mikeGEINE/pandoc-templates](https://github.com/mikeGEINE/pandoc-templates) (accessed 2026-09-23, confidence: Medium). CSL-стили восходят к официальному репозиторию: стиль с `default-locale="ru-RU"` основан на ГОСТ Р 7.0.5-2008 и ГОСТ 7.1-2003, автор признаёт упрощение [CSL Styles — gost-r-7-0-5-2008-numeric.csl](https://github.com/citation-style-language/styles/blob/master/gost-r-7-0-5-2008-numeric.csl) (accessed 2026-09-23, confidence: High). Production-пайплайн `pandoc + --citeproc + pandoc-crossref + Lua-фильтры + --reference-doc + --extract-media` описан в [forpes.ru — Книга в Markdown: сборка DOCX по ГОСТ](https://forpes.ru/post/216899) (accessed 2026-09-23, confidence: Medium). Без постобработки в Word даёт лишь «почти ГОСТ».

Готовые скиллы именно под ГОСТ — есть, но живут вне центральных awesome-списков. Скилл `velikoss/gost-docx` (`npx skills add ... --skill gost-docx`) создаёт .docx с нуля через `docx-js` с точными DXA-параметрами (A4 11906×16838, поля 30/10/20/20 мм) и правит существующие через `unzip → word/document.xml → zip` [skills.rest — gost-docx](https://skills.rest/skill/gost-docx) (accessed 2026-09-23, confidence: Medium), [agentskills.in — gost-docx by velikoss](https://www.agentskills.in/marketplace/%40velikoss/gost-docx) (accessed 2026-09-23, confidence: Medium). Соседний скилл конвертирует «GOST-markdown» в DOCX [skills.rest — mdtodocx](https://skills.rest/skill/mdtodocx) (accessed 2026-09-23, confidence: Low). Высокоуровневые русскоязычные наборы: четыре навыка с требованием «оформлять источники по ГОСТ, APA, IEEE» и учётом ВАК/РИНЦ [GitHub — dubr1k/academic-research-skills](https://github.com/dubr1k/academic-research-skills) (accessed 2026-09-23, confidence: Medium), оркестратор от идеи до подачи по ВАК и ГОСТ Р 7.0.7-2021/7.0.100-2018/7.0.5-2008 [GitHub — KapaSique/paper-maestro](https://github.com/KapaSique/paper-maestro) (accessed 2026-09-23, confidence: Low), набор из 7 скиллов с подзадачей `russian-citations-bibliography` [GitHub — Halfofthesky/claude-russian-editor](https://github.com/Halfofthesky/claude-russian-editor/) (accessed 2026-09-23, confidence: Medium). Важно отделить их от generic-инфраструктуры: официальный скилл Anthropic `anthropics/skills@docx` учит создавать/править/читать Word-документы, но не содержит ГОСТ-параметров [AgenticSkills — DOCX by Anthropic](https://agenticskills.io/skills/docx) (accessed 2026-09-23, confidence: High). В центральных подборках ГОСТ-позиций не обнаружено [GitHub — ComposioHQ/awesome-claude-skills](https://github.com/ComposioHQ/awesome-claude-skills) (accessed 2026-09-23, confidence: High).

MCP именно под ГОСТ — нет; есть только generic MCP манипуляции документами. Сервер `@pandoc/mcp-server` конвертирует Markdown/DOCX/HTML/PDF [FlowHunt — Pandoc MCP Server](https://www.flowhunt.io/mcp-servers/pandoc) (accessed 2026-09-23, confidence: Medium), сервер на python-docx + FastMCP создаёт/правит .docx [GitHub — GongRzhe/Office-Word-MCP-Server](https://github.com/gongrzhe/office-word-mcp-server) (accessed 2026-09-23, confidence: Medium), Rust-реализация со standalone-бинарём [GitHub — hongkongkiwi/docx-mcp](https://github.com/hongkongkiwi/docx-mcp) (accessed 2026-09-23, confidence: Medium). Ни в одном описании нет упоминаний ГОСТ, CSL или ЕСКД. Ближайший «академический» MCP `apaper-mcp` ищет литературу и собирает BibTeX, но пишет в стиле IEEE/TikZ, а не ГОСТ [GitHub — ai4paper/apaper-plugin](https://github.com/ai4paper/apaper-plugin) (accessed 2026-09-23, confidence: Medium).

> Conflicts noted: поле правое — 15 мм в вузовской выписке против 10 мм в большинстве скриптов (объясняется редакциями стандарта и методичками, флаг `--margins` в gostdoc введён именно для этого); кегль заголовков различается между авторскими источниками — арбитр только методичка конкретного вуза; CSL ≈ ГОСТ, а не = ГОСТ (авторы всегда в заголовке ради простоты).
> Gaps: No sources found for MCP с нативной поддержкой ГОСТ из коробки; No sources found for скилл под ГОСТ 2.105-2019 как отдельный артефакт; не найдены независимые бенчмарки качества (процент прохождения нормоконтроля).

### Performance and Benchmarks

No sources found for формального head-to-head бенчмарка с оценкой ГОСТ-соответствия в процентах across LaTeX, python-docx, docx-js, pandoc и AI-генерации. Сравнение ниже реконструировано из документации, issue-трекеров и практик.

Пакет `gost` даёт 16 BibTeX-стилей для ГОСТ 7.0.5-2008 и 7.1-2003 [CTAN: Package GOST](https://ctan.org/pkg/gost) (accessed 2026-09-23, confidence: High, Primary) — наиболее нормативно точный пайплайн для библиографии, но не решает геометрию страниц и шрифты. Проект `latex-g7-32/latex-g7-32` (393 stars, 467 commits) таргетирует ГОСТ 7.32-2001/2017 [latex-g7-32 on GitHub](https://github.com/latex-g7-32/latex-g7-32) (accessed 2026-09-23, confidence: High, Primary), но требует pinned toolchain (шрифты PT Astra/Times, Graphviz, Pygments) и даёт PDF-first, который вузы часто не принимают. Typst-шаблон `modern-g7-32` (259 stars, v0.2.0) автоматизирует титул, нумерацию, библиографию [modern-g7-32 on GitHub](https://github.com/typst-gost/modern-g7-32) (accessed 2026-09-23, confidence: High, Primary) — самый быстрый путь к визуально корректному PDF, но с version-drift и той же проблемой приёмки .docx. Независимое сравнение фиксирует компиляцию в миллисекунды против секунд-минут у LaTeX [TypeTeX: Typst vs LaTeX](https://www.typetex.app/comparisons/typst-vs-latex) (accessed 2026-09-23, confidence: Low).

Pandoc AST осознанно менее выразителен, чем соединяемые форматы: margin size не сохраняется, конверсии expressive→expressive lossy [Pandoc User's Guide](https://pandoc.org/MANUAL.html) (accessed 2026-09-23, confidence: High, Primary). Утечки абстракции подтверждены issue: multilevel list restart [Pandoc issue #4324](https://github.com/jgm/pandoc/issues/4324) (accessed 2026-09-23, confidence: Medium, Primary), Heading 2/3 numbering как flat `1.` [Pandoc issue #1305](https://github.com/jgm/pandoc/issues/1305) (accessed 2026-09-23, confidence: Medium, Primary). Практик из РТУ МИРЭА показывает: дефолтный `book.md -> docx` даёт sans-serif и single spacing, ГОСТ достигается только шаблоном + pandoc-crossref + Lua-фильтрами + CSL [Habr: Book in Markdown with GOST DOCX](https://habr.com/ru/articles/987982) (accessed 2026-09-23, confidence: Medium, Low).

python-docx: секции владеют полями/размером, параграфы — отступами [python-docx: Working with Sections](https://python-docx.readthedocs.io/en/develop/user/sections.html) (accessed 2026-09-23, confidence: High, Primary), но fields не поддерживаются: page numbers — fields [python-docx issue #1297](https://github.com/python-openxml/python-docx/issues/1297) (accessed 2026-09-23, confidence: High, Primary), TOC запрашивается с 2014 и требует ручного `w:fldChar` XML [python-docx issue #36](https://github.com/python-openxml/python-docx/issues/36) (accessed 2026-09-23, confidence: High, Primary), multilevel numbering 1/1.1/1.1.1 открыт с 2021 [python-docx issue #1012](https://github.com/python-openxml/python-docx/issues/1012) (accessed 2026-09-23, confidence: High, Primary). Установка `Heading 1 = Times New Roman` оставляет Calibri из-за `w:asciiTheme` [python-docx issue #805](https://github.com/python-openxml/python-docx/issues/805) (accessed 2026-09-23, confidence: High, Primary). Вывод: raw python-docx без стартового валидированного шаблона ломается ровно на том, что проверяет нормоконтроль.

`docx` (docx-js v9.7.0) — zero-dependency, секции/нумерация/TOC/math/fields [docx on npm](https://www.npmjs.com/package/docx?activeTab=readme) (accessed 2026-09-23, confidence: High, Primary), но дефолтные margins 1 inch в DXA [docx-js: sectionMarginDefaults](https://docx.js.org/api/variables/sectionMarginDefaults.html) (accessed 2026-09-23, confidence: High, Primary). AI-агенты чаще всего ошибаются в конверсии единиц, mismatch style-ID (заголовки выпадают из TOC) и reuse numbering-reference.

ЕСКД-рамки по ГОСТ 2.104 не генерируются ни в одном инструменте нативно — рабочее решение 2012 года рендерило LaTeX в PDF и накладывало рамку через `pdftk` [Habr: Overlay of GOST 2.104 frames](https://habr.com/ru/articles/163315) (accessed 2026-09-23, confidence: Low, Low). Действующий ГОСТ Р 2.104-2023 определяет штампы как thin/thick lines в правом нижнем углу [GOST R 2.104-2023 on cntd](https://docs.cntd.ru/document/1303687640) (accessed 2026-09-23, confidence: Medium, Established). No sources found for нативной генерации рамок в python-docx/docx-js/pandoc.

Для AI-форматирования ГОСТ-бенчмарков нет. Ближайшие общие свидетельства discouraging для наивной генерации: FoFo benchmark (494 инструкции, missing one requirement = fail) [FoFo paper](https://arxiv.org/pdf/2402.18667) (accessed 2026-09-23, confidence: Medium, Primary), DocFormEval (1911 инструкций + Word-JS пар, нужен retrieval API knowledge, иначе галлюцинации) [Text-to-Format paper](https://aclanthology.org/anthology-files/anthology-files/pdf/emnlp/2024.emnlp-main.902.pdf) (accessed 2026-09-23, confidence: Medium, Primary).

> Conflicts noted: Typst-маркетинг (строго быстрее/проще) vs CTAN-экосистема (LaTeX впереди по покрытию журналов) — оба верны для разных deliverables.
> Gaps: нет контролируемого бенчмарка доли прохождения нормоконтроля, нет таксономии ошибок по инструментам, нет датасета отказов нормоконтроля.

### Integration and Compatibility

Формат скиллов един во всех экосистемах, что делает ГОСТ-пайплайн переносимым: skill = директория с `SKILL.md` (YAML frontmatter `name`+`description`) + `scripts/`, `references/`, `assets/`, progressive disclosure [Agent Skills Specification](https://agentskills.io/specification) (accessed 2026-09-23, confidence: High), реализация в [Claude Skills Overview](https://claude.com/docs/skills/overview) (accessed 2026-09-23, confidence: High), [Claude Code Skills](https://code.claude.com/docs/en/skills) (accessed 2026-09-23, confidence: High), [OpenCode Skills](https://v2.opencode.ai/docs/skills) (accessed 2026-09-23, confidence: High), [GitHub About Agent Skills](https://docs.github.com/copilot/concepts/agents/about-agent-skills) (accessed 2026-09-23, confidence: High). Один `docx`-скилл кладётся во все три без переписывания.

Community `docx`-скиллы решают механику Word, но не знают ГОСТ без промпта. Канонический 593-line скилл предписывает: новые документы — `docx-js`, правка существующих — unpack → edit XML → repack, чтение — `pandoc`, превью — LibreOffice + `pdftoppm` [opencode-skills word-document SKILL.md](https://github.com/khadarbashajilan/opencode-skills/blob/main/word-document/word-document/SKILL.md) (accessed 2026-09-23, confidence: Medium). Для ГОСТ-контролей есть ровно нужные примитивы: `page.size` в DXA (A4 11906×16838), `page.margin`, `styles.paragraphStyles` с `font:"Times New Roman"` и `outlineLevel` для TOC, `numbering.config`, `TableOfContents` только по `HeadingLevel`, `headers/footers` с `PageNumber.CURRENT`.

Generic MCP дают те же OOXML-операции как tools: Python-сервер (~40 tools: `open_document`, `get_headings`, `set_page_layout`, `set_headings`, footer `Page CURRENT`, `audit_document`) [docx-mcp-server PyPI](https://pypi.org/project/docx-mcp-server) (accessed 2026-09-23, confidence: High); Node-вариант с `pageSettings` [npm @docx-mcp/docx-mcp](https://www.npmjs.com/package/@docx-mcp/docx-mcp) (accessed 2026-09-23, confidence: Medium); Rust с DOCX→PDF и readonly [lansio docx-mcp](https://115.175.65.104:8004/lansio/docx-mcp) (accessed 2026-09-23, confidence: Low); read-only для Copilot [bradygaster docx-mcp-server](https://github.com/bradygaster/docx-mcp-server) (accessed 2026-09-23, confidence: Medium). Дефолты везде англо-американские (1-inch, Calibri, Letter) — задавать ГОСТ явно.

Под капотом — `python-docx` + `pandoc` + LibreOffice, библиография — LaTeX/CTAN. `python-docx` даёт `section.*_margin`, `Mm()`, `run.font.name='Times New Roman'`, `Pt(14)` [python-docx Section objects](https://python-docx.readthedocs.io/en/latest/api/section.html) (accessed 2026-09-23, confidence: High); критично — стиль, отсутствующий в стартовом файле, молча игнорируется, поэтому стартовать надо с вузовского `.dotx`. Pandoc: `--reference-doc` — contents ignored, styles+margins+header/footer reused [Pandoc Options Affecting Specific Writers](https://pandoc.org/demo/example33/3.4-options-affecting-specific-writers.html) (accessed 2026-09-23, confidence: High). Для LaTeX-first: [CTAN GOST](https://ctan.org/pkg/gost) (accessed 2026-09-23, confidence: High), [CTAN disser](https://www.ctan.org/pkg/disser) (accessed 2026-09-23, confidence: High), [weterans gost 7.32-2017 class](https://github.com/weterans/gost) (accessed 2026-09-23, confidence: Medium).

Практический вузовский пайплайн: взять кафедральный `.dotx` → сгенерировать pandoc reference-doc и перенести стили → оформить ГОСТ 7.32-2017 (А4, 30/10–15/20/20 мм, Times 14, 1.5, 1.25 см, bold-заголовки с новой страницы, сквозная нумерация внизу по центру) как нормировано в [GOST 7.32-2017 GARANT PDF](https://www.imp.uran.ru/sites/default/files/upload/mezhgosudarstvennyy_standart_gost_7.32-2017_sistema_standartov_po_informacii_bi-1_26.10.2018.pdf) (accessed 2026-09-23, confidence: High), [NSTU Checklist GOST 7.32-2017](https://ciu.nstu.ru/kaf/asu/studentam/cheklist_trebovaniiy_k_oformleniyu_otchetovreferatov_v_sootvetstvii_s_gost_7.322017) (accessed 2026-09-23, confidence: High) → писать в Markdown со строгой иерархией Heading 1-3 → `pandoc --reference-doc --toc` → постобработка скиллом/`docx-mcp` → открыть в Word/LibreOffice headless (F9 / `UpdateTOC`) и экспорт PDF для визуальной проверки. Совместимость хорошая, т.к. `.docx/.dotx` — ZIP XML: правка существующего через unpack/XML сохраняет штампы и latent styles, а fresh `docx-js`-создание их отбрасывает.

Жёсткий лимит: ни скилл, ни MCP не кодируют ГОСТ и не умеют пагинацию. Без явного промпта с миллиметрами/пунктами агент выдаёт generic output; TOC демонстрирует layout-engine gap: вставить можно только поле `TOC \o "1-3"`, номера страниц дорисовывает только Word/LibreOffice [python-docx Issue #1207 TOC](https://github.com/python-openxml/python-docx/issues/1207) (accessed 2026-09-23, confidence: High, Primary), [Issue #1403 Auto refresh TOC](https://github.com/python-openxml/python-docx/issues/1403) (accessed 2026-09-23, confidence: High, Primary) — на Linux это `libreoffice --headless macro:///...UpdateTOC`.

> Conflicts noted: правое поле 10 мм (текст ГОСТ) vs 15 мм (вузовские чеклисты) vs 10 мм (7.32-2001); шрифт «не менее 12 pt» в ГОСТе vs enforced 14 pt в чеклистах; нумерация внизу по центру (7.32-2017) vs сверху в делопроизводстве; дефолт docx-js A4 vs Letter — всегда задавать DXA явно.
> Gaps: No turnkey GOST skill в awesome-списках — все `docx` generic; нет automated GOST-валидатора (`audit_document` проверяет OOXML, а не 30/15/20 мм); TOC/номера не рендерятся до открытия в Word/LibreOffice; `.dotx` со сложной первой страницей и титулом без номера требует ручного маппинга стилей.

## Key Findings

Первое и главное: специализированного ГОСТ-MCP не существует — это факт с высокой уверенностью, подтверждённый сквозным поиском по каталогам MCP (mcp.so, Smithery, FlowHunt) и описаниям всех найденных docx/pandoc-серверов, ни один из которых не упоминает ГОСТ, CSL или ЕСКД. Рабочая архитектура 2026 года — это ГОСТ-скилл (промпт + скрипты с захардкоженными миллиметрами) поверх generic-исполнителя (Anthropic docx-skill, python-docx, pandoc, при желании docx/pandoc MCP). Это suggests, что спрашивать «какой MCP ставит ГОСТ из коробки» — неверная постановка; правильно спрашивать «какой скилл поверх какого исполнителя».

Второе: ГОСТ-скиллы существуют, но живут вне центральных awesome-списков — в маркетплейсах skills.rest/agentskills и личных репозиториях. Прямо закрывают 7.32-2017 только `velikoss/gost-docx` (точные DXA-параметры, триггеры «ГОСТ/курсовая/ВКР») и `mdtodocx`, косвенно — `academic-research-skills`, `paper-maestro`, `claude-russian-editor`. This suggests практический путь: не искать «gost» в awesome-claude-skills (там его нет и не будет), а ставить точечно через `npx skills add`.

Третье: официальный скилл Anthropic `docx` — зрелая, но ГОСТ-немизованная инфраструктура (создание через docx-js, правка через unzip/edit/zip, чтение через pandoc, tracked changes). Он уже установлен у пользователя глобально вместе с `docx-mcp` — это хорошая новость: исполнителя докупать не надо, не хватает только ГОСТ-слоя (промпт/форк с миллиметрами). This suggests минимальное действие — добавить ГОСТ-профиль поверх имеющегося, а не менять стек.

Четвёртое: самый надёжный пайплайн сдачи `.docx` — не генерация с нуля, а связка «кафедральный .dotx + Markdown + pandoc --reference-doc + постобработка скиллом/MCP + F9 в Word/LibreOffice». Причина — фундаментальные лимиты библиотек: python-docx не поддерживает fields (номера страниц, TOC, multilevel numbering — открытые issues с 2014/2021 года), pandoc lossy на expressive→expressive (margins, нумерация списков), docx-js требует ручных DXA и outlineLevel, а ЕСКД-рамки не генерирует никто без постобработки. This suggests, что генерация «с нуля» почти гарантирует провал нормоконтроля, а нормализация готового шаблона — прохождение.

Пятое: LaTeX (`gost`, `eskdx`, `latex-g7-32`) и Typst (`modern-g7-32`, единственный живой ГОСТ-проект 2024–2026) дают наиболее нормативно точный PDF, особенно библиографию по 7.0.5-2008, но упираются в требование «сдать .docx» и тяжёлый toolchain. This suggests их ниша — диссертации/статьи с формулами и PDF-сдача; для курсовых/отчётов в Word они — обходной путь через pandoc-мост с потерей fidelity.

## Strategic Recommendations

1. Поставить `velikoss/gost-docx` поверх уже имеющихся `docx` + `docx-mcp` — rationale: единственный скилл с захардкоженными ГОСТ-DXA и триггерами, ставится одной командой, не ломает стек. Evidence: [skills.rest — gost-docx](https://skills.rest/skill/gost-docx) (accessed 2026-09-23, confidence: Medium).
2. Зафиксировать пайплайн «.dotx кафедры + pandoc --reference-doc + скилл-постобработка + LibreOffice F9/экспорт PDF» как стандарт отчётов — rationale: обходит лимиты fields/TOC/нумерации, сохраняет штампы. Evidence: [Pandoc Options](https://pandoc.org/demo/example33/3.4-options-affecting-specific-writers.html) (accessed 2026-09-23, confidence: High); [Habr: Book in Markdown with GOST DOCX](https://habr.com/ru/articles/987982) (accessed 2026-09-23, confidence: Medium, Low).
3. Библиографию вести через CSL `gost-r-7-0-5-2008-numeric` + `--citeproc` (или BibTeX `gost` при LaTeX-треке) — rationale: единственный переносимый способ «почти ГОСТ» для источников, восходящий к официальному CSL-репо. Evidence: [CSL Styles](https://github.com/citation-style-language/styles/blob/master/gost-r-7-0-5-2008-numeric.csl) (accessed 2026-09-23, confidence: High); [CTAN: Package GOST](https://ctan.org/pkg/gost) (accessed 2026-09-23, confidence: High).
4. Не создавать с нуля в `docx-js`/python-docx, а нормализовать готовый (gostdoc `--check`, ручная доводка) — rationale: fresh-генерация отбрасывает latent styles и ломается на theme-шрифтах/полях. Evidence: [GitHub — samikofficial/gostdoc](https://github.com/samikofficial/gostdoc) (accessed 2026-09-23, confidence: Medium); [python-docx issue #805](https://github.com/python-openxml/python-docx/issues/805) (accessed 2026-09-23, confidence: High).
5. ЕСКД-рамки (2.104) вынести из текстового пайплайна в overlay-постобработку (pdftk / Word text-box) и проверять визуально — rationale: нативной генерации нет нигде, это ликliest точка провала нормоконтроля. Evidence: [Habr: Overlay of GOST 2.104 frames](https://habr.com/ru/articles/163315) (accessed 2026-09-23, confidence: Low); [GOST R 2.104-2023 on cntd](https://docs.cntd.ru/document/1303687640) (accessed 2026-09-23, confidence: Medium). Confidence рекомендаций 1–4: Medium–High; 5: Low (single-source + inference).

## Risks and Uncertainties

- Data gaps: не найден MCP с ГОСТ из коробки; не найден скилл под 2.105-2019 как отдельный артефакт; нет бенчмарков доли прохождения нормоконтроля; актуальность части находок (gostdown 2020, G7-32 под 2001) требует перепроверки на 2017.
- Low-confidence claims: заявления авторов скиллов о «точном соответствии» — без внешней валидации; цифры stars/forks расходятся между зеркалами (артефакты кэша).
- Conflicts: правое поле 15 vs 10 мм; кегль заголовков; CSL ≈ ГОСТ, а не = ГОСТ (все авторы в заголовке); дефолт docx-js A4 vs Letter.
- Domain risks: методичка конкретного вуза/кафедры выше любого скилла; требование «только .docx» режет LaTeX/Typst-трек; TOC/номера страниц дорисовываются только Word/LibreOffice — без этого шага документ визуально «почти ГОСТ», но нормоконтроль не пройдёт.
