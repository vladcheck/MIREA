# Практическая работа № 1
## Основы работы с ПО для проектирования схем на базе микроконтроллера

- **Учебный стенд:** «Учтех-Профи» (название указано согласно ТЗ).
- **МК:** STM32F100C8Tx (Cortex-M3, 64 КБ Flash, 8 КБ ОЗУ, LQFP-48).
- **Вариант:** № 25 по табл.9.3 (STM32F1: вход PA0 / выход PB0, порты GPIOA+GPIOB,
  регистры GPIOA→CRL + GPIOB→CRL). Фактические пары проекта — расширение варианта:
  выходы PA0–PA7 (HL1–HL8) + PB8–PB15 (HG1), входы PC13/PC14/PC15/PD0 (SB1–SB4)
  + PB0/ADC (RP1); те же порты GPIOA+GPIOB и те же регистры CRL/CRH. Цепочка
  «ключ → вход → программа → выход → светодиод» сохранена и преумножена.
- **САПР:** KiCad 10 (`PR1_KiCad.kicad_sch`, лист A3) вместо Proteus: стенд
  «Учтех-Профи» собирается как реальная плата, Proteus-модели STM32F100 в
  наличии нет; электрика проверена ERC (0 ошибок), логика — bare-metal кодом
  с корректной картой регистров RM0008 и собранным `firmware/pr1.hex`
  (указывать в Proteus в поле Program File при наличии модели).
- **Цель работы:** ознакомиться с интерфейсом САПР, научиться создавать проект
  и программный файл; построить схему устройства на МК с периферией.

## 1. Перечень элементов (с краткими характеристиками, обозначения по ГОСТ 2.710-81)

| Поз. | Номинал | Назначение / характеристика |
|---|---|---|
| DD1 | STM32F100C8Tx | МК, цепи питания N01/N02, NRST (N24), BOOT0 (N25). `D` — схемы интегральные (табл.1), `DD` — цифровая (табл.2) |
| HL1–HL8 | LED-GREEN, 0603 | Индикация, катоды на GND, аноды через R1–R8 к PA0–PA7 (N03–N10). `H` — индикационные, `HL` — световая сигнализация |
| R1–R8 | 270 Ом, 0603 | Токоограничение HL (~4 мА при 3,3 В) |
| HG1 | KCSC02-105 | 7-сегментный индикатор, общий катод на GND; сегменты A–G, DP на PB8–PB15 (N11–N18). `HG` — индикатор символьный |
| R11–R18 | 270 Ом, 0603 | Токоограничение каждого сегмента HG1 (добавлены по замечанию: у сегментов резисторов не было) |
| SB1–SB4 | SW-SPDT | Кнопки-генераторы уровней на PC13/PC14/PC15/PD0 (N19–N22); каждая на своей вертикали Xv во избежание общих узлов. `S` — коммутационные, `SB` — кнопочный выключатель |
| RP1 | 10 кОм, Bourns 3296W | Потенциометр, движок на PB0 = ADC12_IN8 (N23), фильтр C1. `R` — резисторы, `RP` — потенциометр |
| C1 | 100 нФ, 0603 | Фильтр входа АЦП (N23–N02) |
| C2, C3 | 100 нФ, 0603 | Развязка питания +3V3–GND (разнесены по X во избежание наезда) |
| R9 | 10 кОм | Подтяжка NRST к +3V3 (N24) |
| C4 | 100 нФ | Конденсатор цепи сброса NRST–GND |
| R10 | 10 кОм | Стяжка BOOT0 к GND (N25, загрузка из Flash) |

Позиционные обозначения — обязательная часть по ГОСТ 2.710-81 п.2.2.11
(вид + номер, функция не обязательна). Двухбуквенные коды — по табл.2
обязательного приложения 1 (первая буква = группа). Пояснение кодов вынесено
текстом на поле схемы (требование п.2.2.12). Прописные латинские буквы, арабские
цифры, запись в одну строку без пробелов (п.2.1–2.2.1).

Соединения с МК выполнены зелёным цветом (0 132 0). Неиспользуемые выводы
(PD1, PB1–PB7, PA8–PA15) помечены `no_connect`.

| Ошибка | Проявление | Устранение |
|---|---|---|
| Не-ГОСТ обозначения (U/LED/S/RV) | KiCad ставит IEC-коды по умолчанию | Переименование в DD/HG/HL/SB/RP с пояснением на поле схемы |

## 5.1. Соответствие варианту 25 (честно)

ТЗ требует пару PA0 (вход) / PB0 (выход). В стенде цифровой вывод
показан шире (PA0–PA7 → HL1–HL8, PB8–PB15 → HG1), а PB0 занят аналоговым
входом RP1 (ADC12_IN8) — т.е. требование «выход PB0» покрыто не буквально,
а портами/регистрами тех же GPIOA+GPIOB (CRL/CRH). Функция
«ключ → вход → программа → выход → светодиод» демонстрируется на
SB1–SB4 → HL1–HL8 + HG1.

## 6. Ответы на контрольные вопросы (кратко)

- Proteus — виртуальное моделирование схемы + прошивки до пайки.
- Одной схемы мало: поведение МК задаёт программа (схема + `.hex`).
- В свойствах МК указывается `.hex` в поле Program File.
- Модель в Proteus и МК в IDE должны совпадать, иначе прошивка не ляжет на периферию.
- Вход/выход варианта 25 (STM32): PA0 / PB0; тактирование GPIO — через RCC APB2ENR
  (бит IOPxEN), без него порт мёртв.
- Чтение входов STM32 — регистр IDR; установка/сброс выходов — BSRR (атомарно,
  без read-modify-write).
- DDRx (ATmega) — направление линий; PORTx — выходное состояние/pull-up,
  PINx — чтение входов.
- Чужой вывод / нет GND / нет резистора LED — неработоспособность или сгорание;
  активный высокий — LED горит от `1`, низкий — от `0`;
  кнопке нужна определённость уровня (у нас — SPDT, оба уровня активны).
- Свежесть `.hex` — по дате сборки после компиляции (`ls -la firmware/pr1.*`).
