# Анализ конкурентов
## 1. Введение и формулировка выбранной темы

### 1.1. Выбранная тема проекта
**Название**: Веб-инструмент для создания карт мира для настольных ролевых игр (НРИ)
**Направление**: Графический редактор для Мастеров Игры (Game Masters)
**Тип продукта**: Single Page Application (SPA)
### 1.2. Обоснование выбора архитектуры SPA

Выбор архитектуры Single Page Application обусловлен спецификой задачи создания интерактивного графического редактора:

1.  **Интерактивность:** Редактирование карт требует частого обновления состояния интерфейса (перемещение объектов, изменение слоёв, выбор инструментов) без перезагрузки страницы. SPA обеспечивает мгновенный отклик на действия пользователя.
2.  **Производительность:** Основная нагрузка по рендерингу графики ложится на клиентскую сторону (Canvas/WebGL). Это снижает нагрузку на сервер и уменьшает задержки при взаимодействии.
3.  **Офлайн-режим:** Архитектура SPA позволяет эффективно реализовать технологии Progressive Web App (PWA), что критично для использования инструмента в условиях нестабильного интернет-соединения во время подготовки к сессии.
4.  **Пользовательский опыт:** Отсутствие переходов между страницами создаёт ощущение работы в десктопном приложении, что повышает удобство длительной работы над проектом.

### 1.3. Цель и актуальность проекта

> [!NOTE] Цель проекта
> Разработка легковесного веб-редактора, позволяющего создавать карты мира и локации для настольных ролевых игр без излишней функциональности полноценных VTT-систем.

**Актуальность:**
Существующие решения делятся на две категории: сложные системы для онлайн-игры (VTT) и статичные генераторы. Отсутствует удобный промежуточный инструмент для быстрой отрисовки карт именно для офлайн-сессий, с возможностью экспорта и простым интерфейсом.

## 2. Таблица конкурентов

Для анализа были отобраны 4 веб-сервиса, доступных на территории Российской Федерации: 2 прямых и 2 косвенных конкурента в сфере картографии.

| Тип | Название | Ссылка | Краткое описание |
| :--- | :--- | :--- | :--- |
| Прямой | Inkarnate | https://inkarnate.com | Профессиональный онлайн-редактор карт с библиотекой художественных ассетов |
| Прямой | Dungeon Scrawl | https://www.dungeonscrawl.com | Минималистичный инструмент для быстрого создания схематичных карт подземелий |
| Косвенный | Azgaar's FMG | https://azgaar.github.io | Бесплатный генератор фэнтези-карт с открытым исходным кодом (акцент на автогенерацию) |
| Косвенный | Roll20 | https://roll20.net | VTT-платформа, включающая базовый инструмент для загрузки и разметки карт |

> [!INFO] Классификация
> **Прямые конкуренты** — специализированные веб-инструменты для рисования и проектирования карт (Inkarnate, Dungeon Scrawl).
> 
> **Косвенные конкуренты** — сервисы, где создание карт является вспомогательной функцией или осуществляется автоматически (Azgaar's FMG, Roll20).

## 3. Результаты анализа конкурентных решений
Для анализа применены 2 метода: **SWOT-анализ** и **Сравнительный анализ по критериям**.
### 3.1. SWOT-анализ (на примере Inkarnate)

> [!NOTE] Сильные стороны (Strengths)
> - Высокое качество графических ассетов и текстур
> - Удобная система слоёв для управления объектами
> - Интуитивный интерфейс перетаскивания (drag-and-drop)
> - Возможность экспорта в высоком разрешении

> [!WARNING] Слабые стороны (Weaknesses)
> - Высокая стоимость подписки для доступа к полным библиотекам
> - Тяжёлая загрузка при большом количестве объектов на холсте
> - Обязательная регистрация для сохранения проектов
> - Отсутствие русскоязычной локализации

> [!TIP] Возможности (Opportunities)
> - Внедрение инструментов для схематичного рисования (как у Dungeon Scrawl)
> - Оптимизация производительности для слабых устройств
> - Добавление возможности работы без регистрации

> [!DANGER] Угрозы (Threats)
> - Появление бесплатных аналогов с открытым исходным кодом
> - Блокировки сервисов на отдельных территориях

### 3.3. Выводы по методам анализа

Основная проблема конкурентов — либо излишняя художественная сложность (Inkarnate), либо ограниченный функционал схематичности (Dungeon Scrawl). Пользователю требуется инструмент, позволяющий быстро создать карту с балансом между скоростью и визуальной информативностью, без обязательной регистрации.

## 5. Выводы и точки роста

### 5.1. План улучшений для нашего проекта

На основе Lighthouse-анализа сформированы следующие технические требования:

- Использование формата изображений **WebP/AVIF** для снижения веса ассетов
- **Ленивая загрузка (Lazy Loading)** для элементов карт и иконок
- Соблюдение стандартов **WCAG 2.1** при вёрстке интерфейса
- **Минимизация JavaScript-бандла** (code splitting, tree shaking)
- Реализация **PWA** для возможности работы без интернета

### 5.2. Лучшие практики для заимствования

| Источник | Практика | Обоснование |
| :--- | :--- | :--- |
| **Dungeon Scrawl** | Минимализм интерфейса | Инструменты доступны в один клик, нет перегруженности меню |
| **Azgaar's FMG** | Работа без обязательной регистрации | Снижает порог входа, позволяет сразу начать работу |
| **Azgaar's FMG** | Экспорт в множестве форматов (SVG, PNG) | Гибкость для разных сценариев использования |
| **Inkarnate** | Система слоёв | Упрощает управление сложными композициями карт |

### 5.3. Точки роста (преимущества перед конкурентами)

| Направление | Решение | Конкурентное преимущество |
| :--- | :--- | :--- |
| **Доступность** | Базовый функционал без регистрации | Inkarnate и Roll20 требуют аккаунт для сохранения |
| **Локализация** | Полная русскоязычная поддержка | Ни один из конкурентов не имеет полноценного русского языка |
| **Производительность** | Оптимизация под слабые соединения | Целевой Performance 85+ против 40-60 у прямых конкурентов |
| **Фокус** | Только создание карт (без игровых механик) | Упрощённый интерфейс по сравнению с VTT-системами |
| **Экспорт** | JSON + SVG + PNG | Более гибкий экспорт для дальнейшей обработки |

### 5.4. Итоговое заключение

Конкурентный анализ показал, что ниша инструментов для **создания карт** без излишней функциональности VTT свободна. Существующие решения либо слишком тяжеловесны (Inkarnate), либо слишком примитивны (Dungeon Scrawl).

Предложенный проект займёт промежуточную позицию, делая ставку на:
1.  **Скорость работы** — целевой показатель Lighthouse Performance > 85
2.  **Простоту интерфейса** — минимальное количество кликов до начала рисования
3.  **Техническую оптимизацию** — современные форматы, ленивая загрузка, PWA
4.  **Локализацию** — полная поддержка русского и английского языков
