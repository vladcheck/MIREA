#### База данных
[[ERD]]  
БД у нас в 3 нормальной форме.  
При проектировке БД мы для каждой сущности думаем "какими характеристиками обладает эта сущность в нашей системе".  
Чувствительные данные - любая информация, которая может описать реального человека.  
Персональные уязвимые данные (ФД-152 либо ФД-153 хз) -  
- 1НФ: у каждой сущности есть свой набор полей, которые абсолютно ее описывают. Например, в таблице есть набор пользователь, а каждый пользователь является сущностью User (по ГОСТу пишем в единственном числе, с большой буквы, ЛИБО на английском языке, ЛИБО ТРАНСЛИТОМ (либо - либо)). 
- 2НФ: можно добавить какую-то сущность, которая описывает состояние другой сущности более подробно, например, "Role" пользователя, а сущности эти соединяется по ([[foreign key|FK]],[[primary key|PK]])RoleId (сущность-поле);
- 3НФ: данные валидны, а чувствительные данные - вынесены в отдельную сущность UserPersonalInfo, связаную с User по (FK,PK)Id по связи 1к1 (у одного пользователя может быть ОДНА персональная информация), а пароль захеширован;
#### Тестирование
В СДО есть шаблон тестирования  
Имя тестирующего - ПМ  
Приоритет: Низкий - "захожу на сайт и вижу что-то", Средний - "я что-то нажал и что-то отобразилось" - 1 система, Высокий - "при авторизации пользователь создан или найден" - больше 2 систем. Минимум 2 высоких и 5 средних
>[!info] 2 высоких (на мне), 5 средних (по 2 остальным, мне 1), 8 простых (по 4 всем)
  
Зачет/незачет (в графе) - фактический результат = ожидаемый результат при соблюдении всех условий исполнения
