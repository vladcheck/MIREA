# Практическое занятие №3: Инструкция по выполнению (на основе файла №4)

> [!WARNING]
> Данную практическую работу **невозможно** корректно автоматизировать в виде 4-х последовательных `.sql` скриптов для `run-tests.sh`. Суть работы — это демонстрация конкурентного (параллельного) выполнения транзакций, блокировок и уровней изоляции. Для этого требуется **два параллельных подключения** (два окна терминала), в то время как `run-tests.sh` выполняет файлы строго последовательно в рамках одной сессии.

Ниже представлено пошаговое руководство с командами для двух окон терминала (`psql`) и рекомендации по созданию снимков экрана (скриншотов) для отчета.

---

## 🛠 Подготовка
Откройте **два терминала** (Терминал 1 и Терминал 2) и в каждом выполните вход в базу данных `real_estate_db` через psql (по аналогии с вашим `run.sh`):

```bash
psql -U postgres -d real_estate_db
```

## Часть 1. Вставка, обновление и удаление строки

**Терминал 1:**
1. Создаем таблицу:
   ```sql
   CREATE TABLE a (id integer);
   ```
2. Вставляем строку:
   ```sql
   INSERT INTO a (id) VALUES (1);
   ```
3. Смотрим скрытые системные колонки транзакций:
   ```sql
   SELECT xmin, xmax, * FROM a;
   ```
   📸 **СКРИНШОТ 1:** Вывод таблицы с колонкой `xmin` (ID транзакции).

4. Начинаем явную транзакцию и обновляем строку:
   ```sql
   BEGIN;
   UPDATE a SET id = 2 WHERE id = 1;
   ```
5. Проверяем изменения внутри Терминала 1:
   ```sql
   SELECT xmin, xmax, * FROM a;
   ```

**Терминал 2:**
7. Обращаемся к таблице:
   ```sql
   SELECT xmin, xmax, * FROM a;
   ```
   📸 **СКРИНШОТ 2:** Вывод `SELECT` в двух терминалах рядом. В Терминале 1 видно новое значение `2`, а в Терминале 2 — старое `1`, при этом у старой строки `xmax` уже непустой (что означает наличие новой незафиксированной версии).

**Терминал 1:**
8. Фиксируем изменения:
   ```sql
   COMMIT;
   ```

**Терминал 2:**
9. Проверяем, что обновленная строка теперь видна:
   ```sql
   SELECT xmin, xmax, * FROM a;
   ```

**Терминал 1:**
10. Проверяем удаление:
   ```sql
   BEGIN;
   DELETE FROM a WHERE id = 2;
   SELECT xmin, xmax, * FROM a;
   ```

**Терминал 2:**
13. Проверяем видимость при удалении:
   ```sql
   SELECT xmin, xmax, * FROM a;
   ```
   📸 **СКРИНШОТ 3:** В Терминале 1 пусто, в Терминале 2 строка еще видна, но у нее обновился `xmax`.

**Терминал 1:**
14. `COMMIT;`

**Терминал 2:**
15. `SELECT xmin, xmax, * FROM a;` (строка окончательно исчезает).

## Часть 2. Видимость версии строки на различных уровнях изоляции

**Терминал 1:**
16. Начинаем транзакцию по умолчанию (READ COMMITTED):
    ```sql
    BEGIN;
    SHOW transaction_isolation;
    INSERT INTO a (id) VALUES (3);
    ```

**Терминал 2:**
19. Тоже начинаем транзакцию:
    ```sql
    BEGIN;
    SHOW transaction_isolation;
    SELECT * FROM a; -- Строка со значением 3 пока НЕ видна
    ```
    📸 **СКРИНШОТ 4:** Вывод `SHOW transaction_isolation` и `SELECT * FROM a` в Терминале 2 (пусто).

**Терминал 1:**
21. `COMMIT;`

**Терминал 2:**
22. Снова делаем запрос внутри старой транзакции:
    ```sql
    SELECT * FROM a;
    ```
    📸 **СКРИНШОТ 5:** Строка `3` появилась! Это демонстрация *аномалии неповторяющегося чтения (non-repeatable read)*.
23. `COMMIT;`

**Демонстрация уровня REPEATABLE READ**

**Терминал 1:**
24. Запускаем с другим уровнем изоляции:
    ```sql
    BEGIN ISOLATION LEVEL REPEATABLE READ;
    INSERT INTO a (id) VALUES (4);
    ```

**Терминал 2:**
25. Запускаем на том же уровне:
    ```sql
    BEGIN ISOLATION LEVEL REPEATABLE READ;
    SELECT * FROM a;
    ```

**Терминал 1:**
26. `COMMIT;`

**Терминал 2:**
27. Проверяем еще раз:
    ```sql
    SELECT * FROM a;
    ```
    📸 **СКРИНШОТ 6:** Новой строки `4` **НЕТ**. На уровне REPEATABLE READ мы работаем со снимком данных на момент старта транзакции. Аномалии неповторяющегося чтения не происходит.
28. `COMMIT;`

## Часть 3. Состояние транзакции по CLOG

В этой части можно использовать один терминал.

29. Начнем транзакцию и добавим строку:
    ```sql
    BEGIN;
    INSERT INTO a (id) VALUES (5);
    ```
30. Посмотрим ID нашей транзакции через `SELECT txid_current();` (или системную функцию `pg_xact_status`):
    ```sql
    -- Получаем ID текущей транзакции (вместо '1598' подставить свое значение!)
    -- В современных версиях PostgreSQL можно использовать:
    SELECT pg_xact_status(txid_current()::text::xid8);
    ```
    📸 **СКРИНШОТ 7:** Результат должен показать `in progress`.

31. `COMMIT;`
    Снова выполняем проверку статуса (для ТОГО ЖЕ ID транзакции, который был получен на предыдущем шаге):
    ```sql
    SELECT pg_xact_status('<ВАШ_ID_ТРАНЗАКЦИИ>'::text::xid8);
    ```
    📸 **СКРИНШОТ 8:** Статус должен стать `committed`.

32. Откат транзакции:
    ```sql
    BEGIN;
    SELECT txid_current(); -- Запомните ID
    INSERT INTO a (id) VALUES (6);
    ROLLBACK;
    SELECT pg_xact_status('<ВАШ_НОВЫЙ_ID>'::text::xid8);
    ```
    📸 **СКРИНШОТ 9:** Статус транзакции должен быть `aborted`.

## Часть 4. Блокировки таблицы

**Терминал 1:**
33. Определяем PID нашего первого процесса:
    ```sql
    BEGIN;
    SELECT pg_backend_pid();
    ```
    *Запомните или запишите это число (например, 12948).*
34. Вставляем строку:
    ```sql
    INSERT INTO a (id) VALUES (10);
    ```
35. Обновляем её:
    ```sql
    UPDATE a SET id = id + 1;
    ```
36. Смотрим блокировки:
    ```sql
    SELECT locktype, transactionid, mode, relation::regclass as obj 
    FROM pg_locks 
    WHERE pid = <PID_ИЗ_ПУНКТА_33>;
    ```
    📸 **СКРИНШОТ 10:** Вывод блокировок, ищем строчку с `RowExclusiveLock`.

**Терминал 2:**
37. Определяем PID второго процесса:
    ```sql
    SELECT pg_backend_pid();
    ```
38. Пытаемся создать индекс!
    ```sql
    CREATE INDEX ON a (id);
    ```
    *(Команда должна "подвиснуть", потому что таблица блокирована Терминалом 1).*

**Терминал 1:**
39. Пока Терминал 2 висит, проверяем, чего он ждет:
    ```sql
    SELECT locktype, transactionid, mode, relation::regclass as obj 
    FROM pg_locks 
    WHERE pid = <PID_ТЕРМИНАЛА_2>;
    ```
    📸 **СКРИНШОТ 11:** В Терминале 1 видно блокировку `ShareLock` для второго терминала, которая ждет.

40. `COMMIT;` 
    *(В ту же секунду Терминал 2 "отвиснет" и индекс будет создан).*
    📸 **СКРИНШОТ 12:** Успешно созданный индекс в отвисшем Терминале 2.
